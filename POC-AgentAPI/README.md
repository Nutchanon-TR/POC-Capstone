# ร้านเว็บ: OpenRouter POC

ทดลองคำสั่งภาษาไทย → OpenRouter API จริง → HTML/CSS/JavaScript → preview → สั่งแก้ → เก็บเวอร์ชันและดาวน์โหลด ZIP

## เริ่มใช้งาน

ต้องมี Node.js 20.19 ขึ้นไป ไม่ต้องติดตั้ง package เพิ่ม

1. เปิดโฟลเดอร์นี้ใน terminal
2. ถ้ายังไม่มี `.env` ให้คัดลอก `.env.example` เป็น `.env`
3. ใส่ key ใน `OPENROUTER_API_KEY=` แล้วบันทึก อย่าแชร์ไฟล์นี้หรือ commit ขึ้น Git
4. รัน `npm start`
5. เปิด <http://127.0.0.1:3030>

หรือเปิด `start-poc.cmd` เพื่อเริ่ม server ได้ โมเดลเริ่มต้นคือ `inclusionai/ling-3.0-flash-sante:free` ตามผลทดสอบสร้างและแก้เว็บจริงใน [POC-RESULTS.md](POC-RESULTS.md)

แก้ key แล้วรีเฟรชหน้าเว็บได้เลย Server อ่าน `.env` ใหม่ทุกครั้งที่เริ่มงาน ส่วนการเปลี่ยน port ต้อง restart Server กำหนดค่าผ่าน environment variables ได้เช่นกัน โดยค่าของ process มีลำดับก่อน `.env`

ใช้สอง port: 3030 สำหรับหน้าจัดการ และ 3031 สำหรับเว็บไซต์ที่สร้าง ทั้งสองเปิดเฉพาะบนเครื่องนี้ หาก port ถูกใช้แล้ว เปลี่ยน `PORT` และ `PREVIEW_PORT` ใน `.env` ให้ต่างกัน

## ลองพิสูจน์การสร้างและแก้โค้ด

1. เลือกตัวอย่างร้านอาหาร แล้วกดสร้าง
2. ลองปุ่มกรองเมนูใน preview ดูทั้งขนาดคอมและมือถือ
3. เปิดแท็บโค้ด จะเห็นไฟล์จริงสามไฟล์ พร้อม token เวลา และจำนวน API calls ตามที่ API รายงาน
4. สั่งว่า `เปลี่ยนสีหลักเป็นส้ม เพิ่มเมนูข้าวกะเพรา ราคา 65 บาท`
5. เปิดแท็บเวอร์ชัน เปรียบเทียบ v001 กับ v002 และกดใช้ฉบับเก่าเพื่อสั่งแก้ต่อได้
6. ดาวน์โหลด ZIP แตกไฟล์แล้วเปิด index.html ได้ โค้ดที่สร้างไม่ได้ใช้ build step

POC นี้ใช้โมเดลเดียวสำหรับแต่ละงานและ retry เพื่อซ่อมคำตอบได้อีกหนึ่งครั้ง แสดงขั้นตอนจริงของโปรแกรม ยังไม่ใช่ทีมหลาย agent

## โค้ดถูกเก็บไว้ที่ไหน

```text
data/sites/<UUID>/
  site.json                   # รายการเวอร์ชันและฉบับปัจจุบัน
  versions/v001/
    index.html
    styles.css
    script.js
    metadata.json             # prompt, model, usage, request ID, เวลา, ผลตรวจ
  versions/v002/...
```

การสร้างหรือแก้จะเพิ่มโฟลเดอร์ใหม่ การย้อนเวอร์ชันเปลี่ยนเพียงตัวชี้ฉบับปัจจุบัน รุ่นเดิมยังอยู่ ถ้าแก้จากรุ่นเก่า จะได้หมายเลขเวอร์ชันใหม่ต่อท้าย เก็บข้อมูลบนดิสก์ของเครื่องนี้ ปิดหรือ restart โปรแกรมแล้วโหลดกลับมาได้ ไม่มีฐานข้อมูลและไม่มีการเผยแพร่เว็บขึ้นอินเทอร์เน็ตในขั้นนี้

เมื่อแก้เว็บ ระบบส่งโค้ดสามไฟล์ของฉบับปัจจุบันพร้อมคำสั่งใหม่ไปให้ AI ไม่ส่งทุกเวอร์ชันย้อนหลัง หากคุณกำลังเปิดดูรุ่นเก่า ต้องกด “ใช้ฉบับนี้” ก่อนสั่งแก้

## API, โมเดลฟรี และ token

- key อยู่ฝั่ง Node server ไม่ส่งไป browser และไม่ใส่ใน metadata
- อ่านรายการโมเดลจาก `GET https://openrouter.ai/api/v1/models` และตรวจราคาใหม่ก่อนสร้างทุกงาน
- รับเฉพาะ ID ลงท้าย `:free` ที่ราคา input/output และค่าคำขอถ้ามีเป็นศูนย์ พร้อมกำหนด `provider.max_price` ของ input/output เป็นศูนย์ในคำขอ
- เรียก `POST https://openrouter.ai/api/v1/chat/completions` โมเดลเดียว ไม่มีการสลับไปโมเดลเสียเงิน โมเดลเริ่มต้นตั้งใน `.env` เปลี่ยนตัวฟรีจาก dropdown ได้
- Free tier มี rate limit และความพร้อมใช้งานเปลี่ยนได้ กรณี 401/402/429/503 จะแสดงเหตุผล ไม่ทำผลลัพธ์จำลองแทน
- `MAX_OUTPUT_TOKENS=20000` คือเพดาน output ต่อการเรียก ไม่ใช่โควตารายวัน และไม่รวม input ส่วน reasoning อาจนับรวมในงบ output ตามผู้ให้บริการ ค่าที่โปรแกรมรับได้คือ 1,000–20,000 และยังตรวจเพดานของโมเดลที่เลือกก่อนส่งคำขอ
- มีโอกาสใช้ 2 API calls ถ้าคำตอบแรกเป็น JSON ไม่ครบ หรือ syntax ผิด ทั้งสองครั้งมี usage แยกใน metadata เมื่อสร้างสำเร็จ
- เลือกส่งเป็น JSON ผ่าน prompt เพื่อให้ใช้กับโมเดลฟรีที่ไม่รองรับ `response_format` ได้
- ถ้าโมเดลรองรับ `response_format` จะส่ง `json_object` เพิ่มด้วย และถ้า reasoning ไม่บังคับ จะขอปิด reasoning เพื่อเหลือ token สำหรับโค้ด ผู้ให้บริการอาจจัดการงบ token ต่างกัน ดู usage จริงประกอบ
- Timeout 180 วินาทีต่อ API call ถ้าเกิด timeout หรือ upstream error จะหยุดและให้ผู้ใช้ลองใหม่หรือเลือกตัวฟรีอื่นเอง
- การตรวจอัตโนมัติเช็ก JSON, ไฟล์ครบ, เอกสาร HTML, link ของ CSS/JS และ JS syntax โดยไม่รันโค้ดบน server ยังไม่ใช่การรับรองว่าหน้าตาและทุกฟังก์ชันถูกต้อง

เอกสารทางการ: [API](https://openrouter.ai/docs/api/reference/overview), [การเลือก provider และ max_price](https://openrouter.ai/docs/guides/routing/provider-selection), [สร้าง key](https://openrouter.ai/settings/keys)

## ขอบเขตและการแยก preview

เว็บที่สร้างเปิดผ่านอีก origin และ iframe sandbox อนุญาต JavaScript แต่ไม่ให้เข้าถึง origin ของหน้าจัดการ CSP ปิด network fetch, ส่ง form และ external scripts อนุญาตรูป HTTPS ได้ รูปภายนอกจึงอาจโหลดไม่ขึ้นและเจ้าของรูปจะได้รับ request จาก browser

รองรับหน้าเว็บและ interaction ใน browser เช่นกรองรายการหรือฟอร์มเดโม การรับออเดอร์ การจองจริง การชำระเงิน login และ LINE ยังต้องสร้าง backend และเชื่อมระบบเพิ่มเติม ไม่มีการ execute คำสั่ง AI บนเครื่อง ไม่มี npm install จากโค้ดที่ AI ส่งมา

การป้องกันนี้เหมาะกับ POC บนเครื่อง ยังไม่พร้อมเปิดเป็นบริการสาธารณะ หากพัฒนาต่อควรเพิ่ม auth, job queue, isolation สำหรับการรันโค้ด, quota ของผู้ใช้ และ object storage สำหรับเผยแพร่

## ตรวจระบบ

`npm test` ทดสอบการกันโมเดลเสียเงิน, parsing, syntax, retry, rate limit, การเก็บ/ย้อนเวอร์ชัน, ZIP และ HTTP workflow รวมถึงการไม่ส่ง key ไป browser การทดสอบอัตโนมัติใช้ API จำลองเพื่อไม่กินโควตา ต้องแยกจากผลทดสอบ API จริงใน `POC-RESULTS.md`

สั่งทดสอบ API จริงซ้ำได้ด้วย `node scripts/live-smoke.mjs <model-id:free>` สคริปต์ตรวจราคาก่อนสร้างเว็บร้านอาหารและแก้หนึ่งครั้ง บันทึกเว็บใน `data/sites/` ตามปกติ การรันนี้ใช้โควตา API จริง

ไฟล์หลัก: `server.mjs` จัดการ HTTP และงาน, `lib.mjs` เรียก AI/ตรวจไฟล์/เก็บเวอร์ชัน, `public/` เป็นหน้าจัดการ
