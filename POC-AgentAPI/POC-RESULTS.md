# ผลทดสอบ POC วันที่ 8 ตุลาคม 2026

## ทดสอบซ้ำด้วยเพดาน 20,000 output tokens

ปรับ `.env`, ค่าเริ่มต้น และตัวตรวจค่าสูงสุดของโปรแกรมเป็น 20,000 แล้ว restart server ใช้คำสั่งเดิมจากแท็บของผู้ใช้: เว็บ “พี่เตอร์ติวคณิต” โทนกรมท่า-เหลือง คอร์ส ม.ต้น/ม.ปลาย ราคา ผู้สอน ตารางเรียน และปุ่มดูรายละเอียด โมเดลเดิม `apodex/apodex-1.1-mini:free`

ผลสำเร็จใน 108.868 วินาที เก็บเป็น v001 ของเว็บ `58ed08f8-99a8-495c-9473-82c26179b442` ครบสามไฟล์

| API call | Input | Output | รวม | finish_reason | ผลตรวจ |
|---|---:|---:|---:|---|---|
| ครั้งแรก | 382 | 14,350 | 14,732 | stop | รูปแบบไฟล์ไม่ตรง จึงขอให้ AI แก้ |
| ครั้งที่สอง | 16,367 | 4,938 | 21,305 | stop | ผ่านและบันทึกเว็บ |

รวม 36,037 tokens และ API รายงาน cost 0 ทั้งสองครั้ง คำตอบแรกมี output เกินเพดานเก่า 10,000 จริง โดยครั้งนี้ไม่ถูกตัด แต่ยังต้องซ่อมรูปแบบไฟล์ การเพิ่มเพดานช่วยให้ตอบยาวขึ้น ไม่รับรองว่าโมเดลทุกตัวจะส่งโค้ดถูกต้องเสมอ

ตรวจใน browser แล้วปุ่มดูรายละเอียดคอร์สเปิด modal พร้อมราคาและเนื้อหาคอร์สได้ ภาพอยู่ที่ [proof/poc-20000-details.jpg](proof/poc-20000-details.jpg) หน้า POC แสดงเพดาน output ต่อครั้งเพิ่มแล้ว ชุดทดสอบล่าสุดผ่าน 9 รายการ รวมการตรวจว่าค่า 20,000 ถูกส่งไปเป็น `max_tokens` และยังปฏิเสธโมเดลที่รองรับ output ต่ำกว่าเพดานที่เลือก

ผลด้านล่างเป็นการทดสอบก่อนปรับเพดาน ใช้ค่า 10,000 ตามเวลาที่ทดสอบ

ทดสอบบน Windows, Node.js 20.19.2 ผ่าน OpenRouter key ของผู้ใช้ เก็บ key ใน `.env` และไม่ส่ง key ไป browser ผลด้านล่างมาจาก API จริงและไฟล์ที่เขียนลงดิสก์

## ผลที่สำเร็จ

โมเดล `inclusionai/ling-3.0-flash-sante:free` ตรวจราคาจาก catalogue ก่อนเรียก กำหนดเพดาน output 10,000 tokens, temperature 0.3, reasoning effort none และ provider max_price input/output เป็นศูนย์

| งาน | ฉบับ | เวลา API + ตรวจไฟล์ | Input | Output | รวม tokens | ค่าใช้จ่ายที่ API รายงาน |
|---|---|---:|---:|---:|---:|---:|
| สร้างร้านอาหารครัวบ้านเรา พร้อมปุ่มกรองเมนู | v001 | 16.955 วินาที | 421 | 3,351 | 3,772 | $0 |
| เปลี่ยนสีเป็นส้ม เพิ่มข้าวกะเพราไก่ 65 บาท | v002 | 14.828 วินาที | 3,625 | 3,453 | 7,078 | $0 |
| สั่งผ่านหน้า POC แก้ปี footer และข้อความ LINE เดโม | v003 | 14.858 วินาที | 3,747 | 3,534 | 7,281 | $0 |

แต่ละงานสำเร็จใน 1 API call และจบด้วย `finish_reason: stop` รวมเฉพาะสามงานสำเร็จ 18,131 tokens, $0 ไม่รวมคำขอวิเคราะห์และคำขอที่ล้มเหลวระหว่างพัฒนา ความเร็วและความพร้อมของ free tier เปลี่ยนได้ ตัวเลขนี้เป็นผลทดสอบครั้งนี้

เว็บไซต์เก็บจริงที่ `data/sites/4de64db0-34c8-4352-a8c2-3fae80905416/versions/` มี v001, v002, v003 ครบ ทั้งหมดมี index.html, styles.css, script.js และ metadata.json ตรวจ request ID, prompt, usage และราคา ณ ตอนสร้างได้จาก metadata

## ตรวจใน browser และการเก็บข้อมูล

- เปิดเว็บที่สร้างใน iframe ผ่าน port 3031 ได้ CSS แสดงผลจริง
- กดกรองเครื่องดื่มใน v002 แล้วเหลือรายการเครื่องดื่ม กดอาหารแล้วแสดงสี่รายการ รวมข้าวกะเพราที่เพิ่ม
- เปลี่ยน preview เป็นมือถือ 390px แล้วเปิดเมนูนำทางได้ `aria-expanded` เปลี่ยนและลิงก์แสดงขึ้น
- หน้า POC ที่ความกว้าง 390px จัดส่วนกรอกคำสั่งกับผลลัพธ์เรียงลงมา ไม่มี horizontal overflow
- สั่งแก้จากหน้าเว็บจริงผ่าน `/api/generate` ได้ v003 มีปี 2026 และคำอธิบายว่า LINE เป็นลิงก์ตัวอย่าง
- ใช้แท็บเวอร์ชันย้อนเป็น v001 แล้วกลับเป็น v003 ได้ ไฟล์ทั้งสามฉบับยังอยู่และฉบับปัจจุบันสุดท้ายเป็น v003
- โหลด ZIP ของ v002 ผ่าน HTTP เปิดด้วย .NET ZipArchive และอ่าน UTF-8 พบสามไฟล์ที่เนื้อหาตรงกับ snapshot ทุกไฟล์
- restart server แล้วโหลดประวัติจากดิสก์กลับมาได้
- ภาพหน้าพร้อมใช้อยู่ที่ [proof/poc-desktop.jpg](proof/poc-desktop.jpg)

ชุดทดสอบอัตโนมัติ `npm test` ใช้ stub API และผ่าน 8 รายการ แยกจากหลักฐาน API จริงข้างต้น ครอบคลุมโมเดลเสียเงิน/ราคาเปลี่ยน, JSON และ JS syntax, retry, rate limit, reasoning/output exhaustion, เวอร์ชัน/rollback/path traversal, ZIP และ HTTP/key secrecy

## สิ่งที่พบระหว่างพัฒนา

- North Mini Code ในคำขอช่วงแรก timeout ระหว่างรับคำตอบ และในคำขอถัดมาถูกตัดที่ 10,000 output tokens แม้ retry อีกครั้ง
- Gemma 4 31B free ตอบ 429 โดยระบุ provider Google AI Studio ขณะบัญชียังเหลือโควตาฟรี จึงไม่ได้สรุปว่า key ใช้ไม่ได้หรือโควตารายวันหมด
- Ling ในคำขอก่อนปรับ prompt/parameters ใช้ output เต็ม 10,000 tokens สองครั้งโดยยังไม่ได้ JSON ครบ API รายงาน reasoning 0 และ cost 0 แสดงว่าปัญหา token อาจเกิดจากขนาดโค้ดเองด้วย
- หลังจำกัดขนาดโค้ดในคำสั่งให้ชัด ใช้ reasoning effort none และ temperature 0.3 จึงได้สามงานสำเร็จที่ประมาณ 3,300–3,500 output tokens ไม่ได้แยกทดสอบผลของแต่ละค่าทีละตัว จึงยังระบุไม่ได้ว่าค่าใดเป็นสาเหตุหลัก
- ตั้ง Ling เป็น default ตามผลทดสอบนี้ ยังเลือก North และตัวฟรีอื่นใน dropdown ได้ ไม่ได้ทดสอบ North ซ้ำด้วย configuration สุดท้าย จึงไม่ใช้ผลนี้จัดอันดับคุณภาพโมเดล
- ข้อความที่ AI แต่งเองบางส่วนต้องตรวจแก้ เช่นรายละเอียดอาหาร หรือปี footer ที่เดิมเป็น 2025 การตรวจ syntax ไม่ตรวจความถูกต้องของข้อมูลร้าน

## ข้อสรุปสำหรับขอบเขต POC

พิสูจน์แล้วว่า API สามารถส่งโค้ดเว็บครบชุดให้โปรแกรมบันทึก เปิดดู แก้จากโค้ดเดิม เก็บประวัติ และส่งออก ZIP ได้ เว็บตัวอย่างมี JavaScript ที่กดใช้งานจริงใน browser

ยังเป็นเว็บฝั่ง client บนเครื่อง ไม่มีระบบจอง/ออเดอร์/ชำระเงินจริง ไม่มี LINE integration หรือ deployment และยังไม่ได้ทำทีมหลาย agent ขั้นตอนที่เห็นเป็นงานจริงของโปรแกรมและโมเดลเดียว ความพร้อม free tier และการควบคุมขนาด output ต้องออกแบบเป็นส่วนหนึ่งของระบบต่อไป
