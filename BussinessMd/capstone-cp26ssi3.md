# Pain Point

### ที่มา

Pain point นี้มาจากประสบการณ์ส่วนตัวของผมเอง ผมกับทีมยังเรียนอยู่ในมหาลัย และมีโอกาสไปเข้าร่วมงาน event ต่าง ๆ อยู่บ่อยครั้ง ทั้งงานของมหาลัยเองและงานข้างนอก ส่วนตัวผมชอบเข้าร่วมงานเกี่ยวกับ technology เช่น tech conference และ tech meetup แต่ติดปัญหาเรื่องเวลาและการเดินทางที่ไม่สะดวก เลยมักเข้าร่วมแบบออนไลน์แทนเสมอ

แล้วก็พบว่า ในงานที่ผมอยากมีส่วนร่วมกับกิจกรรม อยากคุยกับคนในงาน อยากได้ connection ใหม่ ๆ หรือแม้แต่อยากเดินดูว่าในงานมีบูธอะไรบ้าง การเข้าร่วมแบบออนไลน์แทบจะทำสิ่งเหล่านี้ไม่ได้เลย ผมกับทีมเลยเก็บ pain point นี้ไว้ แล้ว research หาข้อมูลเพิ่มเติม จนพบปัญหาอื่น ๆ ตามด้านล่าง

### ปัญหาของงานออนไซต์

**ฝั่งผู้จัดงาน**: ต้นทุนการจัดงานสูง ไม่ว่าจะเป็นค่าสถานที่ อุปกรณ์ หรือเจ้าหน้าที่ และต้นทุนเหล่านี้ยังโตตามขนาดงานด้วย

**ฝั่งผู้เข้าร่วม**: จากประสบการณ์ของทีม งาน event ส่วนใหญ่ เช่น meetup สายเทค มักกระจุกอยู่ในกรุงเทพฯ ผู้ที่อยู่ต่างจังหวัดหรืออยู่ไกลจากสถานที่จัดงานต้องเสียเวลาและค่าใช้จ่ายในการเดินทาง ซึ่งอาจรวมถึงค่าที่พักและค่าใช้จ่ายอื่น ๆ จนทำให้บางคนไม่สามารถเข้าร่วมงานได้ รวมถึงคนที่มีข้อจำกัดอื่น เช่น คนมีลูก คนทำงานเป็นกะ หรือคนพิการ ที่เข้าร่วมงานออนไซต์ได้ยากกว่าคนทั่วไป

ปัญหาเหล่านี้แก้ได้ด้วยการจัดงานแบบออนไลน์ แต่ก็จะไปเจอกับ pain point ถัดไป

### ปัญหาของงานออนไลน์

แพลตฟอร์มออนไลน์ส่วนใหญ่ในปัจจุบัน เช่น Zoom, YouTube, Teams มีรูปแบบเหมือนการประชุม หรือก็คือเน้นการบรรยายเพียงฝ่ายเดียวเป็นหลัก ซึ่งถ้าเป็น event สำหรับการบรรยาย แค่นี้ก็อาจจะเพียงพอแล้ว

แต่ event รูปแบบอื่นที่ต้องการ activity ต้องการการมีส่วนร่วมของคนในงาน ต้องการทำ networking หรือต้องการพื้นที่ที่ทำให้เห็นสินค้าหรือผลงานของตัวเอง การจัดออนไลน์ด้วยเครื่องมือเหล่านี้จำลองประสบการณ์แบบนั้นได้น้อยมาก ต่อให้ได้คุยกับใครแล้ว ก็ยังไม่มีช่องทางแลก contact กันในระบบ จบงานแล้วก็ไม่ได้ connection อะไรติดตัวกลับไป

> **ตัวอย่างจริง**: ICML และ ICLR เคยจัด poster session ผ่าน Zoom โดยแยกห้องละโปสเตอร์ ผลคือผู้นำเสนอหลายคนต้องนั่งรออยู่คนเดียวนาน 2 ชั่วโมง เพราะไม่มีใครกล้ากดเข้าห้อง ([NeurIPS Blog](https://blog.neurips.cc/2021/02/12/neurips-2020-online-experiments-gather-town-poster-sessions-and-mementor/))

นอกจากนี้ เมื่อจัดงานแบบออนไลน์ ผู้จัดยังต้องบริหารเครื่องมือหลายตัวไปพร้อมกัน ไม่ว่าจะเป็น Zoom, Google Form, Google Sheet หรือ LINE ซึ่งเพิ่มความยุ่งยากให้กับผู้จัด

### ช่องว่างที่เห็น

ทีมจึงเห็นช่องว่างตรงนี้ และมีไอเดียว่า ถ้าเราทำแพลตฟอร์มที่จัด event แบบออนไลน์ได้ โดยที่ยังจำลองประสบการณ์การเข้าร่วมงานได้เทียบเท่าหรือใกล้เคียงกับการเข้าร่วมงานจริง ก็คงจะดี

### สรุป Pain Point

**งานออนไซต์** — เราแก้ได้ แต่การจัดออนไลน์ทั่วไปก็แก้ได้เช่นกัน

1. **ต้นทุนสูง** (ผู้จัด) — ค่าสถานที่ อุปกรณ์ เจ้าหน้าที่ และโตตามขนาดงาน
2. **ระยะทางกีดกันคน** (ผู้เข้าร่วม) — เวลาและค่าใช้จ่ายในการเดินทางทำให้บางคนเข้าร่วมไม่ได้

**งานออนไลน์** — ปัญหาหลักที่เราแก้

3. **เป็นแค่คนดู** (ผู้เข้าร่วม) — แพลตฟอร์มเป็นแบบประชุม ไม่มี activity และการมีส่วนร่วม
4. **ไม่ได้คุยกับคนในงาน** (ผู้เข้าร่วม) — ไม่เกิดการพบปะหรือ networking แบบงานจริง
5. **คุยแล้วไม่ได้ contact** (ผู้เข้าร่วม) — ไม่มีช่องทางแลกกันในระบบ จบงานแล้วไม่มีอะไรติดตัวกลับไป
6. **ผลงานและบูธไม่มีพื้นที่** (ผู้เข้าร่วม / exhibitor) — ไม่มีที่ให้เดินดูสินค้าหรือผลงาน
7. **ต้องใช้หลายเครื่องมือ** (ผู้จัด) — Zoom + Google Form + Google Sheet + LINE ประกอบกันเอง

# Solution

**Connecta** — แพลตฟอร์มจัดอีเวนต์ออนไลน์ในโลกเสมือน 2D ที่จำลอง**ประสบการณ์การเข้าร่วมงานจริง** ทุกอย่างเกิดขึ้นในพื้นที่เดียวกัน ผู้เข้าร่วมเดินตัวละครไปมาได้เหมือนเดินในงาน

## ทำอะไรได้บ้าง

| ใคร | ทำอะไรได้ |
|---|---|
| **ผู้เข้าร่วม** | ฟัง speaker บนเวที · คุยเป็นกลุ่มกับคนที่ยืนใกล้ (proximity chat / voice) · คุยส่วนตัวใน Meeting Room · แลก contact · ร่วมกิจกรรม (Q&A, โซนยืนเลือกข้าง, reaction) · ยกมือขอพูด · เดินชมบูธ |
| **ผู้จัด / Staff** | สร้างงาน · เปิดลงทะเบียน · วาง agenda ผูก session กับโซนบนแมป · เปิด-ปิด module ตามประเภทงาน · กำหนด role · ดูแลความเรียบร้อย · ดูสรุปผลหลังงาน |
| **Speaker** | stream เสียง + จอ · ยื่นไมค์ให้ผู้ฟัง · จัดการ Q&A ของ session ตัวเอง |
| **Exhibitor** | แต่งบูธ · ใส่ไฟล์และวิดีโอ · เก็บ lead · ดู analytics ของบูธ |

## Use Case

Connecta **ไม่ได้มาแทนงานออนไซต์** แต่เป็นทางเลือกและส่วนเสริมสำหรับงานที่อยากจัดออนไลน์โดยยังได้ประสบการณ์ใกล้เคียงงานจริง

ไม่จำกัดประเภทงาน แต่แบ่งความเหมาะสมได้ 3 ระดับ

### ✅ เหมาะ — งานที่มีทั้งเวที การพบปะ และบูธ

- งานแสดงผลงานโปรเจคจบ / งานแสดงผลงานนักศึกษา
- poster session / นิทรรศการของงานวิชาการ
- open house
- career fair
- สัมมนา / meetup ที่มี networking
- นิทรรศการที่ดูผ่านจอได้ — ซอฟต์แวร์ · ผลงาน · บริการ

### ⚠️ จัดได้ แต่มีข้อจำกัด — บรรยายฝ่ายเดียว

- ใช้ Zoom อาจง่ายกว่า
- แต่ถ้าผู้จัดอยากได้ความมีส่วนร่วม เราให้ลูกเล่นเพิ่มได้ — reaction · Q&A · โซนเลือกข้าง · คุยกันต่อหลัง session

### ❌ ไม่เหมาะ — งานที่ต้องสัมผัสของจริง

- motor show · งานชิมอาหาร · งานโชว์สินค้าที่ต้องจับต้อง
- ประสบการณ์หลักคือการจับต้อง ซึ่งออนไลน์ทำแทนไม่ได้

# Target Group

แบ่งกลุ่มด้วย**พฤติกรรมการจัดงาน** ไม่ใช่ลักษณะทางประชากร โดยใช้ 2 แกนที่ตัดสินว่าระบบเรามีคุณค่ากับงานนั้นไหม

- **ความจำเป็นต้องจัดออนไลน์** — ผู้เข้าร่วมกระจายหลายพื้นที่หรือเดินทางมาได้ยาก
- **ความสำคัญของการพบปะและเดินชม** — คนมางานเพื่อคุย เจอคน และแวะดูบูธ ไม่ใช่แค่นั่งฟัง

| กลุ่ม | ตัวอย่างงาน | ออนไลน์จำเป็น | พบปะ / เดินชม | สถานะ |
|---|---|---|---|---|
| **A. สถาบันการศึกษา** | งานแสดงผลงานโปรเจคจบ · open house · career fair · สัมมนาที่มี guest speaker | 🟢 สูง | 🟢 สูง | 🎯 **หลัก — ทางเข้า** |
| **B. คอมมูนิตี้ที่มีงบ** | meetup ที่บริษัทจัดเอง (DevRel) · user group ของผลิตภัณฑ์ · สมาคมวิชาชีพ | 🟢 สูง | 🟢 สูง | 🎯 **หลัก — ทางโต** |
| **C. งานประชุมวิชาการ** | poster session · นิทรรศการของงานประชุม | 🟡 กลาง | 🟢 สูง | 🔸 รอง |
| **D. องค์กร / ผู้จัดนิทรรศการ** | งานรับสมัครงานของบริษัท · นิทรรศการผลงานหรือบริการที่ดูผ่านจอได้ | 🟡 กลาง | 🟡 กลาง | 🔸 รอง — รองรับได้ แต่ไม่ได้ออกแบบมาเพื่อกลุ่มนี้เป็นหลัก |
| **E. meetup ที่จัดกันเองฟรี** | meetup ชุมชนที่ไม่มีสปอนเซอร์ | 🟢 สูง | 🟢 สูง | ⚪ ใช้ได้ แต่ไม่ใช่เป้าหมายเชิงธุรกิจ — มีความต้องการแต่ไม่มีคนจ่าย |
| **F. บรรยายฝ่ายเดียว** | webinar · อบรมออนไลน์ · ถ่ายทอดสด | 🟢 สูง | 🔴 ต่ำ | ⚪ ไม่ใช่เป้าหมายหลัก — จัดได้ถ้าผู้จัดอยากได้ลูกเล่นการมีส่วนร่วม |
| **G. งานที่ต้องสัมผัสของจริง** | motor show · งานชิมอาหาร | 🔴 ต่ำ | — | ❌ ไม่ใช่เป้าหมาย — ออนไลน์ทำแทนไม่ได้ |

**ทำไม A กับ B**
- **A คือทางเข้า** — ทีมเข้าถึงได้โดยตรงและทดลองกับงานจริงได้ (เช่น งานแสดงผลงานโปรเจคจบของคณะ) · ตลาดมีจริง — One Stop Open House 2026 ของ อว. มีผู้เข้าร่วมทั้งออนไซต์และออนไลน์รวม **200,000+ คน**
- **B คือทางโต** — networking คือเหตุผลที่มางาน · สมาชิกกระจายหลายจังหวัด · **มีงบจ่าย** ต่างจาก E ที่ความต้องการเหมือนกันแต่ไม่มีคนจ่าย

**ใครใช้ · ใครจ่าย**
- **คนจ่าย** — ผู้จัดงาน และ sponsor / exhibitor
- **คนใช้** — ผู้เข้าร่วม · speaker · exhibitor · staff

## 1. ด้านธุรกิจ — โฟกัสที่ event

จุดที่ตีกับ Gather ได้คือ **เราทำเพื่อ event โดยเฉพาะ** ฟังก์ชันทั้งหมดออกแบบมาสำหรับการจัดงาน ไม่ใช่พื้นที่ทั่วไปที่ผู้จัดต้องประกอบเอง

→ ตัวอย่างใน [การใช้งานจริง](#การใช้งานจริง) พิสูจน์ว่ารูปแบบ "เดินดูแล้วคุยกับเจ้าของผลงาน" มีคนใช้จริง แต่ Gather เป็นพื้นที่ทั่วไป ผู้จัดต้องสร้างห้องจาก template และประกอบระบบเอง ไม่มีระบบจุดจัดแสดง เช่น สถานะว่าเจ้าของอยู่ประจำจุดไหม · สถิติว่าจุดไหนคนแวะเยอะ · lead — ซึ่งเป็นสิ่งที่เรามี (⚠️ เช็คฟีเจอร์ปัจจุบันของ Gather ก่อนอ้างใน proposal)

- ลงทะเบียน / ตั๋ว / เช็คอิน ในบัญชีเดียวกับการเข้าโลก 2D
- agenda ที่ session ผูกกับโซนบนแมป + แจ้งเตือน + ปุ่มพาไปห้อง
- บูธที่มี exhibitor · คลังไฟล์ · lead · analytics
- activity สำหรับงาน — Q&A · โซนยืนเลือกข้าง · reaction
- role ของงาน (Organizer · Staff · Speaker · Exhibitor) + moderation
- สรุปผลหลังงาน — no-show rate · session · บูธ · contact ที่แลก
- เปิด-ปิด module ตามประเภทงาน

**จุดแข็งเสริม**
- **จ่ายต่องาน** ตามความจุที่จองล่วงหน้า — เหมาะกับงานที่จัดเป็นครั้ง ๆ มากกว่า subscription รายที่นั่งรายเดือน
- **พร้อมจัดได้เร็ว** — เลือก map preset ไม่ต้องออกแบบแมปเอง
- **เชื่อถือตัวตนได้** — บังคับ login · โหมด INVITE ใช้ชื่อจากรายชื่อที่ผู้จัดอัปโหลด · role badge ออกจาก server ปลอมเป็น speaker ไม่ได้
- **ข้อมูลที่ผูกกับพื้นที่** — รู้ว่าใครแวะบูธไหน อยู่นานเท่าไร ซึ่งหน้าเว็บ event platform ทั่วไปวัดไม่ได้
- **ง่าย ครบ จบในที่เดียว และเร็ว** — ผู้จัดสร้างงานเองได้ เลือกความจุ + ระยะเวลาแล้วเห็นราคาทันที ได้ลิงก์เผยแพร่ในไม่กี่นาที ไม่ต้องคุยกับฝ่ายขาย และไม่ต้องประกอบ Zoom + Google Form + LINE OA เอง

## 2. ด้านโปรเจคจบ — ไม่ต้องชนะขาด

นี่คือโปรเจคจบของทีม 3 คน ประสบการณ์น้อย เวลาจำกัด เรียนไปทำไป budget น้อย — การชนะเจ้าตลาดตรง ๆ ไม่ใช่เป้าหมายที่สมเหตุสมผล และโปรเจคส่วนใหญ่ก็มีตัวที่ดีกว่าอยู่ในตลาดแล้วทั้งนั้น

สิ่งที่สำคัญกว่าคือ **รู้ว่าตลาดมีอะไร · หาช่องว่างเจอ · ตัดสินใจอย่างมีเหตุผล · ทำออกมาได้จริง** — ไม่ใช่ทำสิ่งที่มีอยู่แล้วซ้ำ แต่มีจุดที่แตกต่างชัดเจนตามข้อ 1

# Tech Stack & Architecture

## Stack

| ชั้น | เลือก | เหตุผลหลัก |
|---|---|---|
| Language | **TypeScript** ทั้งระบบ | ชั้น realtime อยู่บน Node อยู่แล้ว ถ้า API ใช้ภาษาอื่นต้องดูแลเครื่องมือและประกาศโครงสร้างข้อมูลซ้ำสองชุด |
| Rendering | **Phaser 3** | tilemap · collision · camera · sprite animation ครบในตัว |
| Map | **Tiled** → export JSON | ไม่ต้องเขียน map editor เอง |
| Web | **Next.js (App Router)** | หน้า public ได้ SEO/OG ใน codebase เดียว |
| Realtime | **Colyseus** | room lifecycle · delta state sync · client SDK สำเร็จรูป |
| API | **NestJS** | โครงสร้างบังคับ เหมาะทีมหลายคน · guard เป็นที่ของ permission |
| Media | **LiveKit** (self-host) | SFU + TURN/TLS ในตัวเดียว |
| DB | **PostgreSQL + Prisma + pgvector** | ข้อมูลเชิง relation + vector สำหรับ RAG ในที่เดียว |
| Cache | **Redis** | MVP ยังไม่ใช้จริง แต่วาง interface ไว้ |
| Storage | **MinIO** (S3-compatible) | ไฟล์บูธ · serve ด้วย signed URL |
| Auth | **OAuth (Google/Microsoft) + magic link · JWT** | บังคับ login ทุกคน ไม่มี guest |
| AI | **LLM API + pgvector** | AI booth bot (RAG) |
| Infra | **Docker Compose + nginx** บน VM ของมหาวิทยาลัย | ฟรี · ย้ายขึ้น cloud ได้โดยไม่ต้องแก้โค้ด · nginx เพราะทีมมีประสบการณ์ |

## Architecture

```
Browser
 ├─ TCP 443 ──→ nginx (TLS) ──┬──→ api        (NestJS   :3000)
 │                             ├──→ realtime   (Colyseus :2567)
 │                             └──→ livekit    (signaling :7880)
 └─ UDP 50000-60000 ─────────────→ livekit    (media ตรง ไม่ผ่าน nginx)
    (fallback: TURN over TLS 443)

api      → postgres :5432 · redis :6379 · livekit :7880 · minio :9000
realtime → postgres :5432 · redis :6379
```

⭐ **media เป็น UDP ผ่าน reverse proxy ไม่ได้ → browser ต้องต่อ LiveKit ตรง** ข้อนี้กำหนดการเลือก infra ทั้งหมด

**สิ่งที่ nginx ต้องตั้งเอง**
- **cert**: certbot + ต่ออายุอัตโนมัติ
- **WebSocket**: ใส่ header `Upgrade` / `Connection` ให้ realtime (Colyseus) และ livekit signaling ไม่งั้นต่อไม่ติด
- **TURN over TLS บน 443**: ใช้ `stream` module + `ssl_preread` แยกตามชื่อโดเมน ให้ HTTPS กับ TURN ใช้พอร์ต 443 ร่วมกัน — ⚠️ ถ้าย้าย TURN ไปพอร์ตอื่น คนบนเน็ตองค์กรที่เปิดแค่ 443 จะเข้าไม่ได้

## Deployment

- **พัฒนาบน localhost ได้เลย ไม่ต้องรอ VM** — ยกเว้นเรื่อง NAT/TURN ที่ localhost ผ่านเสมอ ต้องทดสอบจากเน็ตจริง
- **VM มหาลัย ต้องเช็คก่อน**: public IP · เปิด UDP 50000–60000 inbound · domain + TLS cert จริง · WebSocket upgrade ผ่าน proxy ของมหาลัยได้
  - ทดสอบเร็วสุด: รัน LiveKit บน VM แล้วเข้าจาก**มือถือ 4G** (ห้ามใช้ wifi มหาลัย) ได้ยินเสียง = ผ่านทุกข้อ
- **ถ้า VM ไม่ผ่าน**: แยก LiveKit ไป VPS สิงคโปร์ หรือใช้ LiveKit Cloud

## Spike

ตัวหลักที่ต้องผ่านเพื่อยืนยันว่าโปรเจคนี้ทำได้

| ด้าน | Spike | คำถาม |
|---|---|---|
| **2D** | **S1** Phaser + Tiled | โหลดแมป · เดินชนกำแพง · Phaser ทำงานร่วมกับ Next ได้โดยไม่ leak |
| | **S2** Movement sync | 30 client ลื่นไหม · tick rate เท่าไร |
| **เสียง** | **S3** LiveKit hello-world | 2 client ได้ยินกันไหม |
| | **S4** Proximity audio 🔴 | ทดสอบกับ**คนจริง 8–10 คน** · เปลี่ยนคนที่ได้ยินเร็วแค่ไหน · browser รับได้กี่เสียง |
| **Video / Streaming** | **S5** Speaker streaming | เสียง + จอ จาก 1 → 50 คน · face cam ใน Meeting Room |
| **Network** | **S6** NAT + TURN | เข้าได้จากบ้าน · wifi มหาลัย · 4G · เน็ตบริษัท · VPN |

ค่าตั้งต้น (ยืนยันจาก spike):
- tick rate **10–15 Hz**
- proximity **hysteresis**: subscribe ~8 ช่อง · unsubscribe ~12 ช่อง — ⚠️ ห้ามใช้ค่าเดียวกัน
- bitrate เสียง ~40 kbps/คน · วิดีโอ speaker ~1.5 Mbps

## กฎร่วมของทั้งระบบ

- **ห้ามเชื่อ client** — role check ต้องมีครบ 3 ทาง: REST · WebSocket message · **ตอนออก token ให้ SFU**
- **Module ต้องปิดได้** — `events.modules jsonb` · ปิดแล้ว UI และเมนูต้องหายทั้งหมด ไม่ใช่แค่ disable ปุ่ม
- **Ephemeral ให้ ephemeral จริง** — proximity chat, reaction, Meeting Room ไม่เก็บลง DB
- **ทุกกิจกรรมต้องเขียน analytics** ไม่งั้นถือว่าเป็นของเล่น
- **Reuse ก่อนเสมอ** — ของที่ reuse บ่อยสุด: websocket broadcast, presence, ตาราง contact/lead, แมป Tiled

## 1. Account & Platform

- **Auth — บังคับ login ทุกคน** ⭐ M
    - Google / Microsoft OAuth เป็นทางหลัก · Magic link เป็นทางสำรอง
    - **ไม่มี guest / anonymous join** — ตัดสินใจแล้ว เพราะ guest ทำให้ ban ไม่ได้ผล · lead ไม่มีข้อมูลติดต่อ · analytics เพี้ยน
    - แยก *สมัครสมาชิก* ออกจาก *ลงทะเบียนงาน* — login ครั้งเดียวใช้ได้ทุกงาน
    - ⚠️ **JWT ห้ามฝัง event role** — role เปลี่ยนระหว่างงานได้ ต้องเช็คจาก DB/cache ทุกครั้ง
- **App role** M — `USER` / `PLATFORM ADMIN` · แยกคนละแกนกับ event role
- **Edit Profile — โปรไฟล์ 2 ชั้น** ⭐ M
    - PUBLIC: ชื่อ · avatar · องค์กร · ตำแหน่ง · ความสนใจ · bio — ทุกคนในงานเห็น
    - PRIVATE: อีเมล · เบอร์ · LinkedIn · เว็บ — **เห็นได้เมื่อแลก contact กันแล้วเท่านั้น**
    - Preset avatar (ไม่มี custom)
    - toggle `เปิดให้ทุกคนในงานเห็นช่องทางติดต่อ` (ปิดเป็นค่าเริ่มต้น)
    - toggle `ไม่รับคำขอแลก contact` — ปิดรับทั้งหมด
- **Platform Console** (เฉพาะ PLATFORM ADMIN) S
    - รายการ event ทั้งหมด · ระงับงานที่ผิดกฎ · system health (concurrent, SFU/TURN, storage)
    - ⚠️ เข้างานคนอื่น**ต้องมี badge มองเห็นได้ ห้ามล่องหน** · ทุกการใช้อำนาจลง audit log และ organizer เห็นได้

## 2. Organizer Dashboard (ก่อนงาน)

- **Event CRUD** ⭐ M
    - ข้อมูลงาน: ชื่อ · คำอธิบาย · วันเวลา · cover
    - **Access Mode**: `PUBLIC` (ใครสมัครก็เข้าได้) / `INVITE` (รหัสตั๋วหรืออยู่ในรายชื่อ CSV)
    - ⚠️ **โหมด INVITE: ชื่อที่แสดงมาจากรายชื่อที่ organizer อัปโหลด ผู้ใช้แก้เองไม่ได้** — เป็นสิ่งเดียวที่ทำให้การยืนยันตัวตนมีความหมาย

    - เลือก map preset (3 แบบ)
    - `Organizer` 1 คน (เก็บเป็นฟิลด์ `owner_id` ไม่ใช่ role แยก) + `Staff` ได้หลายคน
- **Agenda / Session management** ⭐ M
    - สร้าง session: หัวข้อ · เวลาเริ่ม-จบ · โซนบนแมป · speaker ที่ผูก (หลายคนได้)
    - **session เป็นจุดผูกของ** Q&A · speaker streaming · notification · analytics ว่าใครเข้า session ไหน
    - ปุ่ม "พาไปห้อง" วาร์ปไปจุดที่ session จัด
    - `sessions(id, event_id, title, starts_at, ends_at, zone_id, status)` · `session_speakers` · `session_interests`
    - Test: session เวลาซ้อนกัน · แก้เวลาตอนงานกำลังจัด · ลบ session ที่มี Q&A ค้าง
- **Role management** ⭐ M
    - assign ได้ทั้งก่อนงาน (dashboard) และระหว่างงาน · เชิญด้วยอีเมล
    - **Staff assign ได้เฉพาะ Speaker/Exhibitor** — กัน privilege escalation ต้องปฏิเสธที่ server ไม่ใช่ซ่อนปุ่ม
    - `event_members(event_id, user_id, roles text[], assigned_by, assigned_at)` — **roles เป็น array** ไม่งั้นทำ multi-role ไม่ได้
    - `audit_logs(event_id, actor_id, action, target_id, reason, created_at)`
    - เตือนถ้าถึงเวลาเริ่มงานแล้วไม่มี organizer/staff online เลย
    - Test: assign ตอนคนนั้น online ต้องอัปเดตทันทีไม่ต้อง refresh · ถอด role speaker ตอนกำลัง stream ต้องตัด stream · โอนสิทธิ์จนไม่เหลือ organizer ต้องห้าม
- **Booth setup** S 💰 — สร้างบูธเปล่า + assign exhibitor
- **Sponsor setup** C 💰 — ชื่อ · โลโก้ · ลิงก์
- **Billing** C 💰 — Stripe **test mode** เท่านั้น · จองความจุล่วงหน้า จ่ายตามที่จองไม่ใช่ตามที่มาจริง

## 4. Inside the Virtual Event

### 4.1 Roles (ระดับ event · 1 คนมีได้หลาย role)

**เส้นแบ่ง: Staff ทำได้ทุกอย่างที่ย้อนกลับได้ · Organizer ทำสิ่งที่ย้อนกลับไม่ได้**

| Role | จำนวน | ทำอะไรได้ |
|---|---|---|
| `ORGANIZER` | **1 คน** | ทุกอย่าง รวมสิ่งที่ย้อนกลับไม่ได้ — ลบงาน · โอนสิทธิ์ · จ่ายเงิน/ความจุ · เผยแพร่งาน |
| `STAFF` | หลายคน | ทุกอย่างในงาน **ยกเว้น 4 ข้อข้างบน** — moderation · แก้ setting หน้างาน · เลื่อนเวลา session · assign Speaker/Exhibitor · ดู analytics |
| `SPEAKER` | หลายคน | streaming · ยื่นไมค์ · เปิดกิจกรรม · จัดการ Q&A **เฉพาะ session ของตัวเอง** |
| `EXHIBITOR` | หลายคน | จัดการบูธที่ถูก assign · เห็น lead + analytics **ของบูธตัวเอง** |
| `ATTENDEE` | — | ค่าเริ่มต้นของทุกคน |

- ทุก role ต้อง login · **สิทธิ์ = union ของทุก role** ไม่ใช่ hierarchy
- **Role badge บนแมป** (sprite+CSS) — ⚠️ **ต้องออกจากฝั่ง server** เป็นกลไกกันปลอมตัวเป็น speaker
- Moderator ไม่ใช่ role แยก — เป็นความสามารถของ staff และ organizer

### 4.2 Map & Avatar

- **2D room จาก Tiled map (3 preset)** ⭐ M — ไม่ทำ map editor ในเว็บ
- **Movement sync + presence** ⭐ M — เป็น channel ที่ reaction, proximity chat, สถานะบูธ, โซนยืนเลือกข้าง ใช้ร่วมกัน
    - ⚠️ ต้องจัดการ **ghost connection** (ปิดแท็บแล้วตัวละครค้าง) ไม่งั้นตัวนับ concurrent เพี้ยนแล้วบล็อกคนจริง
- **Minimap + ปุ่มวาร์ปไปโซน** S — กันคนหลงทางแล้วออกไปเลย
- **Onboarding ครั้งแรก** S — สอนสั้น ๆ ตอนเข้าโลก 2D ครั้งแรก: เดิน · เข้าใกล้คนเพื่อคุย · กดบูธ · ปุ่มวาร์ป
    - ไม่เกิน ~1 นาที · ข้ามได้ · แสดงครั้งเดียวต่อบัญชี (เปิดดูซ้ำได้จากเมนู)
    - เหตุผล: คนที่ไม่เคยบังคับตัวละครถ้าไม่เข้าใจในไม่กี่นาทีแรกจะออกจากงานไปเลย

### 4.3 Communication

- **Reaction / emote** M — ชุด 5 อัน 👏 ❤️ 😂 ❓ 🔥 · `❓` นับ realtime แสดงในแดชบอร์ด speaker
    - rate limit ~3 ครั้ง/วินาที · aggregate ที่ server ก่อน broadcast · cap ไอคอนที่ render ~30
    - ไม่ทำ reaction เชิงลบ (เปิดช่องให้ bully speaker)
- **Public event chat** M — แผงข้าง ทุกคนในงานเห็น · เก็บใน memory เฉพาะช่วงงาน
- **Proximity text chat** ⭐ M — ลอยเหนือหัว 5-8 วิ แล้วหาย · ไม่เก็บลง DB
- **Proximity voice chat** 🔊 M — ดังตามระยะห่าง
    - ⚠️ **ต้องใช้ SFU** เพราะการเปลี่ยนคนที่ได้ยินต้องเป็นการเปลี่ยน subscription ไม่ใช่สร้าง connection ใหม่
    - ต้องหาค่ารัศมีและ hysteresis จาก spike
- **Speaker streaming** 🔊 M — เสียง + จอ กระจายทั้งห้อง · one-to-many โหลดคนละแบบกับ proximity ต้อง spike แยก
- **ยื่นไมค์ (Pass the Mic)** 🔊 S — speaker ให้ผู้เข้าร่วมพูดถึงทุกคนได้ชั่วคราว เหมือนยื่นไมค์ให้คนในงานจริง · **ใช้ได้ทั้งแมป** ไม่ผูกกับพื้นที่ใด
    - **ขอ**: ผู้เข้าร่วมกด ✋ ยกมือได้จากทุกที่ในแมป → speaker เห็นรายชื่อเรียงตามเวลา (หรือกดที่ avatar ของใครก็ได้บนแมปเพื่อยื่นตรง ๆ)
    - **ยื่น**: speaker กดยื่นไมค์ → ผู้รับต้อง**กดรับก่อน** ไมค์จึงเปิด (ไม่มีใครถูกเปิดไมค์โดยไม่รู้ตัว)
    - **ระหว่างถือ**: เสียงไปถึงทุกคนที่ได้ยิน speaker เท่ากับ speaker · เดินไปไหนบนแมปก็ยังถือไมค์อยู่ · มี badge "ถือไมค์" ออกจาก server · ถือได้ครั้งละ 1 คน
    - **คืน**: speaker ดึงคืนได้ทุกเมื่อ · คืนอัตโนมัติเมื่อผู้ถือกดคืนเอง / หลุดการเชื่อมต่อ / speaker หยุด stream / session จบ
    - ⚠️ สิทธิ์พูดต้องออก **token ใหม่จาก server** และเพิกถอนตอนคืน — ห้ามแค่เปิดไมค์ฝั่ง client
    - Test: ผู้ถือไมค์หลุดเน็ต · speaker หลุดขณะยื่นไมค์อยู่ · session มี speaker หลายคน ใครยื่นใครดึงคืนได้ · กดยื่นซ้อนสองคน
- **Video face cam** 🔊 S — ใช้ใน Meeting Room และ speaker เท่านั้น
- **⚠️ ไม่มี Direct Message** — ตัดโดยเจตนา การตามต่อหลังงานย้ายไปที่การแลก contact
- **ข้อแลกเปลี่ยนที่ยอมรับ** — ไม่เก็บ chat = report ย้อนหลังไม่ได้ แลกกับการไม่ต้องแบกภาระ PDPA ของข้อความ

### 4.4 Moderation & Safety M

- **mute / kick (ชั่วคราว) / ban (ถาวร)** — ทำได้โดย STAFF และ ORGANIZER
- **report** → report queue ให้ staff ตรวจ · ลบข้อความและคำถาม Q&A ที่ไม่เหมาะสม
- **audit log ทุกการกระทำ** — ใครทำอะไรกับใคร เมื่อไหร่ เพราะอะไร
- **สวิตช์ฉุกเฉิน** — ปิดรับคนเข้าใหม่ / ปิดไมค์ทั้งงาน
- ban ได้ผลจริงเพราะบังคับ login — เป็นผลตอบแทนโดยตรงของการตัด guest

### 4.5 Activity

- **โซนยืนเลือกข้าง A / B** M — ป้ายในแมป Tiled คนเดินไปยืนโซนที่ตรงกับตัวเอง
    - **ไม่มี logic ใหม่เลย** — ใช้ป้ายในแมป + movement + proximity chat ที่มีอยู่แล้ว
    - ผลลัพธ์เหมือน live poll แต่ใช้ตัวละครเดินเลือก ซึ่งต้องมีพื้นที่จึงทำได้
- **Q&A + upvote** S
    - พิมพ์คำถาม → คนอื่น upvote (1 คน 1 เสียง ถอนได้) → เรียงตามคะแนน (สลับดู "ล่าสุด" ได้)
    - speaker/staff ทำเครื่องหมาย `กำลังตอบ` / `ตอบแล้ว` / `ซ่อน`
    - จบ session → คำถามที่ยังไม่ได้ตอบรวบส่งให้ speaker
    - **โหมดไม่ระบุชื่อ** — คนทั่วไปเห็นเป็นไม่ระบุชื่อ แต่ staff เห็นว่าใครส่ง · organizer ปิดโหมดนี้ได้
    - `session_questions(id, session_id, author_id, text, is_anonymous, status, created_at)`
    - `question_votes(question_id, user_id)` — ⚠️ **UNIQUE (question_id, user_id)** กันกดรัว
    - ไม่ทำ downvote · reply/threading (กลายเป็น forum)

### 4.6 Booth (module เปิด-ปิดต่องาน) S 💰

- **โครงสร้าง** — organizer สร้างบูธเปล่า + assign เจ้าของ → exhibitor แต่งเอง
    - 1 บูธมีได้หลาย exhibitor (ผลัดกันเฝ้า) · 1 คนดูแลได้หลายบูธ
- **หน้าบูธ** — เดินเฉียดเห็นชื่อ+โลโก้+คำอธิบายสั้น · กด interact เห็นหน้าเต็ม (cover · รายละเอียด · ลิงก์)
    - **คลังไฟล์** — PDF/สไลด์/รูป ดูในเว็บด้วย PDF.js
    - **วิดีโอแนะนำ** — ฝัง YouTube/Vimeo **ไม่โฮสต์เอง**
- **สถานะคนเฝ้าบูธ (ต้องมองเห็นจากภายนอก)** — `ว่าง` / `ไม่ว่าง` / `ไม่อยู่`
- **Lead capture** 💰 — ปุ่ม **"ขอให้ติดต่อกลับ"** → export CSV
    - ⚠️ **ห้ามใช้คำว่า "สนใจ"** ที่กำกวม · ต้องมีข้อความข้างปุ่มว่า *"บูธจะเห็นชื่อ องค์กร และอีเมลของคุณ"* ไม่งั้นขัด PDPA
- **AI booth bot (RAG)** 🤖 S — ตอบจากเอกสารบูธตอนไม่มีคนเฝ้า · ใช้ไฟล์ชุดเดียวกับคลังไฟล์
- **Booth analytics** — คนแวะกี่คน · อยู่นานเฉลี่ย · โหลดอะไร · ได้ lead กี่ราย (ใช้เป็น sponsor report ได้เลย)
- **ไฟล์อัปโหลด** — เก็บที่ MinIO/S3 ไม่ใช่ใน DB · ⚠️ **ตรวจ MIME type จริงที่ server ไม่เชื่อนามสกุล** · serve ผ่าน signed URL ที่หมดอายุ
- Test: คนเฝ้าบูธเน็ตหลุดตอนคุย · exhibitor ถูกถอด role ตอนกำลังเฝ้าบูธ · อัปโหลดไฟล์เปลี่ยนนามสกุล

### 4.7 การแลกช่องทางติดต่อ (Contact Exchange) S

- **กลไก** — A กด `แลก contact` → B เห็นคำขอบนการ์ดโปรไฟล์ของ A → B กด `แลก` = **เปิดเผยของทั้งคู่พร้อมกัน** + แจ้งเตือนสองฝ่าย
- **ไม่มีปุ่มปฏิเสธ** — ไม่กดคือไม่แลก คนขอไม่รู้ว่าถูกปฏิเสธ · ปัดการแจ้งเตือนทิ้งได้แต่คำขอยังอยู่บนการ์ดโปรไฟล์ เปลี่ยนใจกดทีหลังได้
- **ไม่มีกล่องคำขอแยก** — คำขอขึ้นบนการ์ดโปรไฟล์ ไม่ต้องมี inbox
- `contact_exchanges(from_user, to_user, event_id, created_at)` — แลกครบ = **มีสองแถวสวนทางกัน** ไม่มีคอลัมน์สถานะ
    - ⚠️ **UNIQUE (from_user, to_user, event_id)** — ส่งซ้ำไม่ได้ กันตื๊อ
- **แผง "คนในวงนี้"** — คนที่อยู่ในรัศมีเดียวกันตอนนั้น + ปุ่มแลกในแถว (reuse presence)
- toggle ไม่รับคำขอ + จำกัดจำนวนคำขอต่อชั่วโมง · คำขอหายเมื่อจบงาน
- **Export CSV + vCard (.vcf)** — คุณค่าปลายทางของฟีเจอร์นี้ ทุกอย่างก่อนหน้ามีไว้เพื่อให้ถึงจุดนี้

### 4.8 Meeting Room S

- ห้องเป็นพื้นที่บนแมป **คนแรกที่เข้าไปเป็นหัวห้อง** — ไม่ต้องมีระบบจอง ตารางเวลา หรือคิว
- หัวห้องตั้งได้ว่า `public` (ใครกดเข้าก็ได้) หรือ `private` (ต้องขอเข้าก่อน หัวห้องกดรับ)
- คนอื่นเห็นรายการห้องที่เปิดและจำนวนคนในห้อง แต่**ไม่ได้ยินเสียงและไม่เห็นข้อความข้างใน**
- ในห้องได้ครบชุด — ข้อความ เสียง กล้อง · ไม่เก็บอะไรลง DB
- Test: หัวห้องออกขณะยังมีคนอยู่ → **โอนหัวห้องให้คนถัดไป ไม่ใช่ปิดห้องทิ้ง** · คำขอเข้าห้องต้องหมดอายุถ้าหัวห้องหลุด · ⚠️ คนนอกพยายาม subscribe เสียงห้อง private → **ปฏิเสธที่ server ตอนออก token**

### 4.9 Sponsor C 💰

- `sponsors(event_id, name, logo_url, link)` — ไม่ทำเป็น role (คนของ sponsor คือ EXHIBITOR)
- แสดง 2 จุด: **หน้า landing ของงาน** + **หน้า loading ตอนเข้าโลก 2D**
- ⚠️ ห้าม pop-up โฆษณาบังจอ · ต้องปิดทั้งชุดได้ถ้างานไม่มีสปอนเซอร์

# SDG

## SDG 10 — Reduced Inequalities (ลดความเหลื่อมล้ำ)

- **Goal**: ลดความเหลื่อมล้ำทั้งภายในประเทศและระหว่างประเทศ
- **Target 10.2**: ส่งเสริมให้ทุกคนมีส่วนร่วมทางสังคม เศรษฐกิจ และการเมือง โดยไม่ถูกกีดกันจากอายุ เพศ ความพิการ เชื้อชาติ ถิ่นกำเนิด หรือสถานะทางเศรษฐกิจ
- **เราทำยังไง**: คนต่างจังหวัด · คนมีลูก · คนทำงานเป็นกะ · คนพิการ เข้าร่วมงานและสร้าง connection ได้เท่าคนที่อยู่ใกล้สถานที่จัดงาน
- **วัดด้วย**: สัดส่วนผู้เข้าร่วมแยกตามจังหวัด (จากข้อมูลลงทะเบียน)

## SDG 4 — Quality Education (การศึกษาที่มีคุณภาพ)

- **Goal**: สร้างหลักประกันว่าทุกคนได้รับการศึกษาที่มีคุณภาพอย่างครอบคลุมและเท่าเทียม และส่งเสริมการเรียนรู้ตลอดชีวิต
- **Target 4.3**: ให้ทุกคนเข้าถึงการศึกษาระดับอาชีวะและอุดมศึกษาที่มีคุณภาพได้อย่างเท่าเทียม
- **เราทำยังไง**: งานของสถาบันการศึกษา เช่น open house และงานแสดงผลงาน เปิดให้นักเรียนต่างจังหวัดเข้ามาดู ถาม และคุยกับอาจารย์และรุ่นพี่ได้ โดยไม่ต้องเดินทาง
- **วัดด้วย**: จำนวนผู้เข้าร่วมแยกตามจังหวัด และการเข้าชมบูธในงานของสถาบัน

## SDG 13 — Climate Action (การรับมือการเปลี่ยนแปลงสภาพภูมิอากาศ)

- **Goal**: เร่งลงมือรับมือกับการเปลี่ยนแปลงสภาพภูมิอากาศและผลกระทบที่เกิดขึ้น
- **เราทำยังไง**: ลดการเดินทางไปงาน ซึ่งเป็นแหล่งปล่อยก๊าซเรือนกระจกสำคัญของการจัดอีเวนต์
- **วัดด้วย**: อธิบายเชิงคุณภาพเท่านั้น — ⚠️ **ไม่มี Carbon Impact Report ในระบบ** จึงไม่เคลมตัวเลข และไม่ผูกกับ target ย่อยข้อใด

**ข้อจำกัดที่ต้องยอมรับเอง**
- ออนไลน์ไม่ได้ปล่อยคาร์บอนเป็นศูนย์ — server · bandwidth · อุปกรณ์ผู้ใช้ยังใช้พลังงาน
- ต้องมีอุปกรณ์และอินเทอร์เน็ตที่ดีพอ — ไม่ได้ช่วยคนที่ไม่มีสิ่งเหล่านี้
